## DESTAQUES DO DIA

### **OpenAI — Lançamento da Release 2.30.0 do SDK Python**

**O que mudou:** A OpenAI liberou uma atualização crítica do SDK (release 2.30.0) que alinha os tipos de resposta aos esquemas de itens expandidos e adiciona o campo `keys` para ações de computador (Click, DoubleClick, Drag, Move, Scroll).

**Para que serve:** Essa atualização garante que a integração de agentes que usam o Computer Use seja absurdamente mais precisa. Agora é possível enviar atalhos de teclado (`keys`) combinados com cliques de mouse, o que simula perfeitamente a interação humana real (como um Shift+Click ou Ctrl+Drag).

**Como aplicar hoje:** Atualize a biblioteca com `pip install --upgrade openai==2.30.0`. Se a Holdworks está construindo agentes que operam interfaces legadas ou web apps complexos via Computer Use, comece a usar o parâmetro `keys` para executar atalhos diretamente na chamada de ação, reduzindo o número de passos do agente.

**Impacto:** 🔥 Alto — Fundamental para quem está desenvolvendo agentes de automação de desktop/browser.

---

### **Anthropic — Persistência com Filesystem Memory Tools**

**O que mudou:** A Anthropic adicionou suporte nativo para ferramentas de memória baseadas em sistema de arquivos (Filesystem Memory Tools) no commit #1247.

**Para que serve:** Agentes agora podem persistir estado, aprender com interações passadas e armazenar contexto de longo prazo em arquivos locais de forma segura, sem a necessidade imediata de pendurar um banco de dados externo (como Redis ou Pinecone) na arquitetura inicial.

**Como aplicar hoje:** Utilize no Claude Code ou Agent SDK para criar agentes de atendimento ou de código que "lembram" das preferências do usuário entre as sessões. Basta adicionar `tools: ["filesystem_memory"]` nas configurações do agente.

**Impacto:** 🔥 Alto — Reduz a complexidade da arquitetura para agentes com memória de longo prazo.

---

### **OpenAI — GPT-5.4 Mini e Nano em Produção**

**O que mudou:** Confirmação oficial do lançamento dos modelos `gpt-5.4-mini` e `gpt-5.4-nano` na Responses API. O Mini suporta tool search e computer use, enquanto o Nano é focado estritamente em velocidade e custo, suportando apenas compaction.

**Para que serve:** É a consolidação da estratégia de tiering de modelos. O Nano é a ferramenta perfeita para tarefas "burras" de alto volume (classificação, extração simples de dados). O Mini é o sweet spot para agentes rápidos que precisam orquestrar ferramentas externas.

**Como aplicar hoje:** Implemente um roteamento inteligente na arquitetura da Holdworks. Direcione requests de triagem inicial e extração de dados para o `gpt-5.4-nano` e deixe o `gpt-5.4-mini` para as integrações com ferramentas (tool calling). Deixe o GPT-5.4 Pro apenas para raciocínio profundo.

**Impacto:** 🔥 Alto — Permite uma redução drástica de custos operacionais (COGS) mantendo a eficiência da arquitetura de agentes.
