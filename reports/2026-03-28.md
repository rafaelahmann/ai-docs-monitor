## DESTAQUES DO DIA

### **OpenAI — A Revolução Silenciosa no Computer Use**

**O que mudou:** A OpenAI liberou a release 2.30.0 do SDK Python, adicionando o campo `keys` para ações de computador (Click, DoubleClick, Drag, Move, Scroll) e alinhando os tipos de resposta aos esquemas de itens expandidos. Houve também um commit recente de segurança (Pin GitHub Actions) melhorando o CI/CD.

**Para que serve:** Essa atualização transforma a forma como agentes operam interfaces. Agora é possível enviar atalhos de teclado (`keys`) combinados com cliques de mouse simultaneamente. Isso simula a interação humana real (como um `Shift+Click` para selecionar múltiplos itens ou `Ctrl+Drag`), reduzindo drasticamente o número de passos e tokens necessários para um agente completar uma tarefa na tela.

**Como aplicar hoje:** Atualize a biblioteca da Holdworks com `pip install --upgrade openai==2.30.0`. Se você está construindo agentes que operam sistemas legados ou web apps complexos, injete o parâmetro `keys` nas chamadas de ação para executar atalhos diretamente.

**Impacto:** 🔥 Alto — Fundamental para quem desenvolve agentes de automação de desktop ou browser.

### **Anthropic — Memória Persistente sem Banco de Dados**

**O que mudou:** A Anthropic adicionou suporte nativo para ferramentas de memória baseadas em sistema de arquivos (Filesystem Memory Tools) no commit #1247 do SDK. Além disso, o recurso `thinking-display-setting` entrou em GA (General Availability).

**Para que serve:** Agentes agora podem persistir estado, aprender com interações passadas e armazenar contexto de longo prazo diretamente em arquivos locais. Isso elimina a necessidade imediata de pendurar um banco de dados vetorial (como Pinecone ou Redis) na arquitetura inicial. O `thinking-display-setting` permite esconder o "raciocínio" do modelo da interface do usuário final, mantendo a tela limpa.

**Como aplicar hoje:** Utilize no Agent SDK para criar agentes internos na Holdworks que "lembram" das preferências da equipe entre as sessões, apenas adicionando a tool de filesystem memory. Ative o `thinking-display-setting` para melhorar a UX dos clientes finais, guardando os logs de raciocínio apenas no backend.

**Impacto:** 🔥 Alto — Reduz drasticamente a complexidade da arquitetura para agentes com memória.

### **OpenAI — Tiering de Modelos com GPT-5.4 Mini e Nano**

**O que mudou:** Confirmação oficial do lançamento dos modelos `gpt-5.4-mini` e `gpt-5.4-nano` na Responses API. O Mini suporta tool search e computer use, enquanto o Nano é focado estritamente em velocidade e custo, suportando apenas compaction.

**Para que serve:** É a consolidação da estratégia de tiering. O Nano é a ferramenta perfeita para tarefas de alto volume e baixa complexidade (classificação, extração simples de dados). O Mini é o sweet spot para agentes rápidos que precisam orquestrar ferramentas externas.

**Como aplicar hoje:** Implemente um roteamento inteligente no sistema de gestão da Holdworks. Direcione requests de triagem inicial para o `gpt-5.4-nano` e deixe o `gpt-5.4-mini` para as integrações com ferramentas. Reserve o GPT-5.4 Pro apenas para raciocínio profundo.

**Impacto:** 🔥 Alto — Permite uma redução drástica de custos operacionais (COGS) mantendo a eficiência.
